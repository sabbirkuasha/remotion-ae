# Goal

**Anyone who makes an animation in Remotion can export it to After Effects, and an After Effects user can take it
from there without ever learning Remotion.**

Remotion is for making animation with code (by developers, or generated by AI). After Effects users don't want
to learn Remotion. remotion-ae is the bridge: one export command on the Remotion side, one script to run on the
After Effects side, and the result is an ordinary, editable After Effects project.

Remotion videos are React code and After Effects can't open them. The only official bridge goes the other way
(After Effects → Lottie → Remotion).

## What "done" means

1. **Works on any Remotion project, unchanged.** The person who made the animation doesn't have to rewrite it,
   use special components or learn anything new.
2. **It looks the same.** Frames rendered by After Effects match the frames Remotion renders, checked with an
   automatic side-by-side comparison, not by eye alone.
3. **It is editable, not baked.** Text is real text, shapes are shape layers, motion is a few eased keyframes,
   scenes are layers with the right in and out points. Only what After Effects can't express (canvas, WebGL,
   exotic CSS) comes across as video, placed where it belongs.
4. **It is one step on each side.** One command produces a script; running it in After Effects builds the whole
   project (and one Undo removes it again).
5. **It degrades honestly.** Anything that can't be translated is reported, never silently dropped.

## How we get there

- **Done (Phase 1):** projects made with the remo player, whose whole edit is data (`timeline.json`). This built
  and proved the After Effects side: the Scene format, the builder, the bridge and the comparison tool.
- **Next:** capture any Remotion composition while it plays: read every element on every frame and rebuild it
  as After Effects layers and keyframes. See [plan.md](plan.md).
